# Run log

**Support card** · filled in during a run of the [design cycle](../../README.md), and read by the tools that work from a record

> **AI-made.** Drafted by Claude (AI) from Anna (@annaothercrow)'s solo design-thinking toolkit. The fields come from the log Anna wrote by hand during her first run (19.09.2026). See [Who made what](#who-made-what) and [Sources](#sources).

Board version: [run-log.excalidraw](run-log.excalidraw). Open it in Excalidraw or in VS Code.

A sheet you fill in while a run happens. It gets opened before the run starts, and the lines go in as things happen. One per run, never one per day.

In ACE Workshop a run is an item on the [board](https://github.com/orgs/An-na-other-Context/projects/1), logged on its issue. How the run-log fields appear on an issue is *open, not decided for ACE Workshop yet.*

## Why it exists

The book never needs a record tool, because it always puts two people in the room. For Ask 5x why it calls pairs ideal: one person leads the talk, the other documents (Toolbox p. 68). Alone there is no second person, so this sheet takes the documenting job.

## The state-of-the-day line

It has no file of its own. It is the line at the top of the run log, and the "State, in one line" in every tool's bookmark. Three agreed answers, then one detail.

| Answer | What it means |
|---|---|
| good | Things start without a push. |
| flat | Things start, but each step needs deciding first. |
| overloaded | The deciding is the cost. Starting is the wall. |

Then one detail: what's on top today, in a short clause. For example: slept badly · noise · an appointment later · really looking forward to this.

- **Three words, never a number.** No scale and no score. Nothing here is aimed at you.
- **Written before the run, never after.** Written afterwards, it turns into a verdict on the run. Written before, it describes the day.
- **It never judges the output.** A good run on an overloaded day and a thin run on a good day are both information about the run. Neither says anything about you.

The three answers are Claude's wording of how Anna describes her days. They are hers to change.

## How it's used

- **One per run, never per day.** There is no streak, no history, nothing to keep up between runs.
- **Your words, your spelling.** Nothing gets tidied afterwards. The unedited version is the one that stays readable later.
- **It isn't a tracker.** The abstract of a study on self-tracking for neurodivergent people says self-tracking "imposes substantial interpretive and emotional demands" (abstract, quoted). The study worked with six people with autism and/or ADHD (attention deficit hyperactivity disorder) in a workshop; three of them then self-tracked for two weeks. A log written during a run asks nothing of you between runs.
- **An aborted run still gets a log.** Stopping is always allowed, and where and why the run stopped is part of the record.

## Where this goes

Six tools take the run log as input. That is why it came first among the supports.

| Tool | What it takes from the log |
|---|---|
| [AEIOU](../../2-observe/aeiou/aeiou.md) (activities, environments, interactions, objects, users) | the whole log, read for each of the five letters, with you as the user |
| [Customer journey map](../../2-observe/customer-journey-map/customer-journey-map.md) | the timeline as steps, the state lines as highs and lows |
| [Jobs to be done](../../1-understand/jobs-to-be-done/jobs-to-be-done.md) | this run as one of the two or more moments the tool asks for |
| [Retrospective sailboat](../../7-reflect/retrospective-sailboat/retrospective-sailboat.md) | what pushed (wind) and what slowed (anchor), already written down before the retrospective starts guessing |
| [Feedback capture grid](../../6-test/feedback-capture-grid/feedback-capture-grid.md) | the questions field, straight into the grid's questions corner |
| [Lessons learned](../../7-reflect/lessons-learned/lessons-learned.md) | this log beside the other logs of a stretch of runs |

The [gentle why](../gentle-why/gentle-why.md) leans on it too: alone, the run log documents while you ask.

## Where it does not apply

- **Between runs.** No daily entry, nothing to catch up on.
- **As a report written afterwards.** The log stays as it was written. Sorting and reading it is the job of the tools above.

## Where it comes from

- **Not a book tool.** The book always has a second person documenting (p. 68). Alone, the sheet stands in for that person.
- **19.09.2026, Anna's first run.** Anna (@annaothercrow) wrote a log by hand during the run, with no template. It still fed five of the toolkit's tool pages. Claude read the fields out of that log and named them in advance, so naming them doesn't eat the start of a run.
- **20.09.2026, one of six supports.** It came first, because six kept tools take a log as input and nothing produced one. With it, Observe has something to read.
- **The day line, the same day.** The toolkit counted 14 sheets asking for "State, in one line", all in the same words. Nothing said what an answer looks like, so two runs couldn't be compared. The three answers fill that gap.
