# Cycle map

**The whole cycle** · how the tools of the [design cycle](../README.md) hang together

> **AI-made.** Drafted by Claude (AI) from Anna (@annaothercrow)'s solo design-thinking toolkit. The cycle, its phases and every kept tool are Anna's choices. The order inside each phase, the decision points and where the loops return to are Claude's reading: an argument about how a run flows, not a fact. See [Who made what](#who-made-what).

Board version: [cycle-map.excalidraw](cycle-map.excalidraw). Open it in Excalidraw or in VS Code.

## How a cycle runs in ACE Workshop

- **It starts from a research question** (or a few), built on a **design thesis**. How to word both is open: item [#28](https://github.com/An-na-other-Context/ace-workshop/issues/28).
- **Seven phases:** Understand · Observe · Define point of view · Ideate · Prototype · Test · Reflect. Each phase makes artifacts with the tools below, and the findings get documented.
- **A run is an item** on the [ACE Workshop board](https://github.com/orgs/An-na-other-Context/projects/1): a session of setting out to do something, logged on its issue. The board's **Phase** field says which phase a run belongs to.
- **The design board** ([design/](../../../../design/README.md)) is the research and design place in one. The GDD mind map on it is an artifact of Ideate.
- **Now (14.11.2026):** the cycle has just started and sits in phases 1–3. No solution can be known yet.

## The chain, phase by phase

What each tool needs before it can start, and what it hands on. The letters say which support to open while using it (see [Badges](#badges)).

### 1 · Understand

Can't start without: a trouble actually hit, and some record of it.

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [Problem statement](../1-understand/problem-statement/problem-statement.md) | a trouble, and a record or memory of it | one "How might we" sentence → critical items, How might we | Q W M |
| [Jobs to be done](../1-understand/jobs-to-be-done/jobs-to-be-done.md) | at least two moments, as records | jobs → the journey map, the problem statement's "who has the need", the critical items | L Q M |

### 2 · Observe

Can't start without: a record of a real session (notes, a log, a voice memo).

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [AEIOU](../2-observe/aeiou/aeiou.md) | a moment, and notes from during or right after it | a pattern → the problem statement, as a definition to check | L Q |
| [Customer journey map](../2-observe/customer-journey-map/customer-journey-map.md) | a job, and one moment | problem areas with owners → problem statement, critical items | L Q M |

### 3 · Define point of view

Can't start without: findings from the first two phases (jobs, a pattern, low points).

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [Critical items diagram](../3-define/critical-items-diagram/critical-items-diagram.md) | the findings, with quotes | eight elements and the questions they raise → How might we | M |
| [How might we](../3-define/how-might-we/how-might-we.md) | findings, or the eight elements | one or two questions → Ideate | M |
| [Define success](../3-define/define-success/define-success.md) | a subject: this run, this cycle | the measure → MVP, testing criteria, the 2x2 matrix's axes, NABC's benefit | M D |

### 4 · Ideate

Can't start without: a written question to have ideas about.

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [Brainstorming](../4-ideate/brainstorming/brainstorming.md) | the How might we question | clusters of ideas → 2x2 matrix | M S |
| [2x2 matrix](../4-ideate/2x2-matrix/2x2-matrix.md) | idea cards, and two axes named first | one to three ideas → NABC | none: its axes are the criteria |
| [NABC](../4-ideate/nabc/nabc.md) (need, approach, benefit, competition) | one surviving idea | the cross → the assumption a prototype tests | M S |
| [Special brainstorming](../4-ideate/special-brainstorming/special-brainstorming.md) · open in Anna's toolkit | a round that circles | ideas from another angle → back to clustering | M |
| [Analogies & benchmarking](../4-ideate/analogies-and-benchmarking/analogies-and-benchmarking.md) · open in Anna's toolkit | a round that circles | ideas borrowed from other worlds | M S |

Special brainstorming and analogies are the two ways out when a round circles (Anna's ledger, 20.09.2026). Their "needs" and "gives" here are Claude's reading.

### 5 · Prototype

Can't start without: an assumption worth testing, written as a sentence.

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [Kinds of prototypes](../5-prototype/kinds-of-prototypes/kinds-of-prototypes.md) · reference | (looked up when choosing a form) | the kind and its resolution | none |
| [Prototype to test](../5-prototype/prototype-to-test/prototype-to-test.md) | the assumption | a built prototype and a planned run → Testing sheet | S D |
| [Exploration map](../5-prototype/exploration-map/exploration-map.md) | experiments, each with expectation and result | the record across runs, and the next target zone | L |
| [MVP](../5-prototype/mvp/mvp.md) (minimum viable product) · rarely | small experiments that already held, and the success measure | a built thing → Test; results → the exploration map | M |

### 6 · Test

Can't start without: a prototype, and criteria for what would count as verified.

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [Testing sheet](../6-test/testing-sheet/testing-sheet.md) | a prototype, criteria written first, three or four questions, something that records | findings → feedback grid, exploration map | D |
| [Feedback capture grid](../6-test/feedback-capture-grid/feedback-capture-grid.md) | a run and its recording | a new point of view → problem statement; ideas → brainstorming | L W |

### 7 · Reflect

Can't start without: a run that actually happened, even a stopped one.

| Tool | Needs | Gives | Badges |
|---|---|---|---|
| [Retrospective sailboat](../7-reflect/retrospective-sailboat/retrospective-sailboat.md) | one finished run | one measure → the next run (where it's written: open) | L M W |
| [Lessons learned](../7-reflect/lessons-learned/lessons-learned.md) · once per stretch | a stretch of runs, and their logs | a few actions → Define success, the next run's plan | L |

## Badges

A letter on a tool means: open that support card while doing this step.

| Badge | Support | When it's opened |
|---|---|---|
| L | [Run log](../supports/run-log/run-log.md) | opened first, stays open the whole run; the day line sits at its top |
| M | [Discernment matrix](../supports/discernment-matrix/discernment-matrix.md) | at every step where something gets chosen; never for capturing or sorting |
| W | [Gentle why](../supports/gentle-why/gentle-why.md) | when a cause is wanted, not a symptom; stops at the first sign of discomfort |
| Q | [5W+H questions](../supports/5w-h/5w-h.md) | when a question is missing, or a step comes out blank |
| D | Day line (in the [run log](../supports/run-log/run-log.md)) | written before the run and before any sheet that asks; never after |
| S | [Sketch](../supports/sketch/sketch.md) | when a box says draw; never a reason to stop |

## The three loops

- **Small loop, inside one tool:** the clarity check at the end of a sheet doesn't pass → another cycle of the same tool.
- **Middle loop, inside one run:** the need doesn't hold → back to brainstorming. The prototype didn't hold → build again. Neither is a failure; both are the tool working.
- **Big loop, run to run:** Reflect writes one measure, and that measure shapes the next run. *Where the measure is written in ACE Workshop is open, not decided yet* (the toolkit writes it into its ledger).

A run ends at its last decision point, not at exhaustion. Stopping is always allowed, and the run still gets logged.

## Where a run stalls

A phase can't start without its input.

| To start | You need | Which comes from |
|---|---|---|
| Understand | a trouble actually hit | a real run, or the last retrospective's measure |
| Observe | a record of a session | the run log |
| Define point of view | findings: jobs, a pattern, low points | Understand and Observe |
| Ideate | a written question | How might we |
| Prototype | an assumption in one sentence | the NABC cross |
| Test | criteria for what counts as verified | the testing sheet's plan, Define success |
| Reflect | a run that happened | anything above, even a stopped run |

## What the map doesn't decide

1. **How long a run is.** No fixed time, no timebox: short cycles until a clarity check passes (Anna, 19.09.2026).
2. **Which optional tools to use.** Kinds of prototypes, MVP and Lessons learned are looked up when a run needs them, and skipped when it doesn't (Anna, 20.09.2026).
3. **When to stop mid-run.** Stopping is always allowed, and the run log still gets written (Anna, 19.09.2026).
4. **What the tools are for.** Making games, not filling sheets: the sheets gather what works in which situation; Anna builds the game (Anna's words).
